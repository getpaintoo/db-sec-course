# Практика 9. Анализ и исправление SQL-инъекций

## Цель работы

Проверить, как SQL-инъекция возникает при конкатенации пользовательского ввода в запрос, и исправить уязвимые места через параметризованные запросы, whitelist допустимых идентификаторов и минимальные привилегии роли приложения.

## Учебный стенд

| Объект | Назначение |
|---|---|
| `injection_lab.users` | Пользователи для проверки сценария входа |
| `injection_lab.tasks` | Задачи для проверки фильтрации и поиска |
| `injection_lab.audit_log` | Учебный журнал событий |
| `injection_app` | Ограниченная роль приложения без прямого доступа к таблицам |

## Найденные уязвимости

| Сценарий | Уязвимая функция | Payload | Риск |
|---|---|---|---|
| Проверка логина | `vulnerable_login` | `alice' OR '1'='1' --` | Обход пароля и получение чужих учетных записей |
| Фильтр по статусу | `vulnerable_tasks_by_status` | `new' OR '1'='1` | Раскрытие задач вне выбранного фильтра |
| Текстовый поиск | `vulnerable_search_tasks` | `x%' OR '1'='1' --` | Возврат всех строк вместо результатов поиска |

Причина во всех трех случаях одинаковая: пользовательская строка соединяется с SQL-текстом через конкатенацию и начинает интерпретироваться как часть команды.

## Исправления

| Было | Стало | Почему безопаснее |
|---|---|---|
| `username = '` + ввод + `'` | `username = $1` | Драйвер передает значение отдельно от текста SQL |
| Динамический `WHERE status = '...` | `WHERE status = p_status` | Payload сравнивается как обычная строка |
| Произвольное поле сортировки | Whitelist `allowedSortFields` | В SQL попадают только заранее разрешенные идентификаторы |
| Прямой доступ роли к таблицам | `EXECUTE` только на `safe_*` | Даже при ошибке приложения доступ ограничен безопасным API |

## Проверка

Команда:

```bash
make p9
```

Ожидаемые контрольные результаты:

| Проверка | Ожидаемый результат |
|---|---:|
| `vulnerable_login_payload` | Больше 0 строк |

| `safe_status_new` | 2 строки |
| `vulnerable_status_payload` | 5 строк |
| `safe_status_payload` | 0 строк |
| `vulnerable_search_payload` | 5 строк |
| `safe_search_payload` | 0 строк |

## Вывод

SQL-инъекция возникает не из-за самого SQL, а из-за смешивания кода запроса и данных пользователя. Основная защита: использовать параметры для значений, whitelist для динамических идентификаторов и минимальные права для роли приложения. В выполненном стенде один и тот же payload успешно меняет поведение уязвимых функций, но не влияет на исправленные варианты.
