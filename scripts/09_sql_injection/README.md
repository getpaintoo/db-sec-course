# Практика 9. Анализ и исправление SQL-инъекций

Практика моделирует типовые SQL-инъекции в отдельной схеме `injection_lab`: обход проверки логина, расширение фильтра по статусу и обход текстового поиска. Для каждого случая рядом есть исправленный вариант с параметризованным запросом.

## Запуск

```bash
docker compose up -d
make p9
```

## Что внутри

- `setup.sql` — создает стенд, тестовые данные, уязвимые функции `vulnerable_*`, безопасные функции `safe_*` и ограниченную роль `injection_app`;
- `verify.sql` — проверяет, что payload расширяет выборку только в уязвимых функциях, а безопасные функции воспринимают ввод как данные;
- `safe-patterns.js` — примеры небезопасной конкатенации и исправления через параметры `$1`, `$2` и whitelist для `ORDER BY`;
- `theory/09_sql_injection_report.md` — отчет с анализом, мерами исправления и выводом.

## Ожидаемая логика проверки

- `vulnerable_login('alice'' OR ''1''=''1'' --', 'wrong-hash')` возвращает пользователей без знания пароля, потому что ввод попадает в SQL-код;
- `safe_login(...)` на том же payload возвращает `0` строк, потому что значения передаются параметрами;
- роль `injection_app` не имеет прямого `SELECT` на таблицы и может выполнять только безопасные `SECURITY DEFINER`-функции.
